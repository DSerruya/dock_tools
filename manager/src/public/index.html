📖 How to add a script
Language
Ruby
Entry Point
ruby main.rb
Build Command (if using Bundler)
bundle install
Branch
main
stdout buffering: Ruby buffers stdout inside Docker so logs may not appear in real time. Fix by adding $stdout.sync = true at the top of your Ruby script (recommended).
If you cannot edit the script, use stdbuf -o0 ruby main.rb as the entry point instead — but note that stdbuf must be available in the container image.

Private repo: Generate a GitHub PAT with Contents: read scope and paste it in the GitHub Token field.
Language
Python
Entry Point
python -u main.py
Build Command (if using pip)
pip install -r requirements.txt
Branch
main
stdout fix: Use python -u main.py (unbuffered mode) so print() output appears immediately in logs. Alternatively call sys.stdout.flush() after each print or set PYTHONUNBUFFERED=1 as an environment variable.

requirements.txt: If your repo has a requirements.txt, add pip install -r requirements.txt as the Build Command.
Language
Node.js
Entry Point
node index.js
Build Command (if using npm)
npm install
Branch
main
No buffering issues: console.log() is unbuffered by default in Node.js — logs appear in real time without any extra flags.

package.json required: Your repo must have a package.json at the root if you set a Build Command. Without it the container will error on npm install.
Language
TypeScript
Entry Point
npx ts-node index.ts
Build Command
npm install
Branch
main
ts-node: Use npx ts-node index.ts to run TypeScript directly without a separate compile step. Requires typescript and ts-node in your package.json devDependencies.

Pre-compiled: Alternatively compile first — set Build Command to npm install && npm run build and Entry Point to node dist/index.js.
